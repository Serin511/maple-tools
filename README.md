# 메이플 계산기

메이플스토리를 위한 계산기입니다. 일반·에디셔널 잠재능력과 추가옵션 재설정 장사 수익, 어빌리티 고급 재설정 최적 전략, 추가옵션 재설정 중단점을 계산합니다.

**[사용하기 →](https://serin511.github.io/maple-tools/)**

## 특징
- 공식 확률표 기반 3줄 조합 정확 열거 (이탈 1/5·1/20, 중복 제한 옵션 재계산 규칙 반영)
- 유→레 천장 스택(0~107) 이월을 마르코프 체인으로 정확 계산
- 판매/홀드 최적 정지 판정, 미라클데이(등급업 확률 ×2) 지원
- 부위별 특수 잠재: 모자 쿨감, 장갑 크뎀, 장신구 드메, 올스탯(제논)
- 올스탯%는 STR·DEX·INT·LUK에 항상 합산하며 HP에는 합산하지 않음
- 프라임 큐브 모드: 레전드리 1줄 고정 후 2·3줄 재설정(기존/신규 선택 적용), 일반 재설정↔프라임 전환 시점도 최적화
- 프라임 모드를 켜면 **고정할 1줄 옵션 → 자동 최적화**를 기본 선택. 현재 부위·레벨의 첫 줄 후보와 프라임 미사용을 비교해 재설정 1회당 기대 이득이 가장 큰 정책을 선택하며, 직접 고정 옵션을 지정할 수도 있음

잠재능력 장사의 지원 범위, 가격 구간·천장 이월·프라임 가정과 해석값·시뮬레이션의 차이는 [잠재능력 장사 모델](docs/potential-model.md)을 참고하세요.

## 에디셔널 잠재능력 장사

상단 **에디셔널 잠재 장사** 메뉴 또는 `#/additional-trade`에서 사용할 수 있습니다. 에디셔널 메소 재설정 결과를 매입·판매하는 장사의 기대 수익을 계산합니다. 기존 [에디셔널 전략](docs/additional-model.md)은 재설정 자체의 스탯 효율 전략을 다루며, 이 계산기와 별도 기능입니다.

- 시작 등급(기본 에픽), 아이템 부위·레벨, 매입가·수수료와 등급별 메소 재설정 비용 입력
- 일반 잠재능력 장사와 공통 장비 설정 사용, 실패 스택은 장비 설정에서 입력하고 등급업 확률·천장은 고정값 적용
- 오른쪽의 넓은 **판매가** 패널에서 목표 주스탯 환산값·모자 쿨감·장갑 크뎀 조건과 시세를 직접 추가; 미리 채워진 가격 템플릿은 없음
- 등급 공통 시세(기본) 또는 등급별 시세 선택, 쿨감·크뎀은 입력 합계 이상으로 판정
- 에디셔널 전략 기준의 스탯 환산 효율(크뎀 1%는 주스탯 4% 기본), 주스탯별 부스탯 고정 매핑, 기준 캐릭터 레벨(기본 290)
- 가격 조건을 만족한 결과를 모두 판매하거나, 판매·계속 재설정을 기대 수익 기준으로 자동 최적화
- **프라임 에디셔널 큐브 모드** 지원(가격 기본값 **14억 메소**). 고정할 첫 줄의 자동 최적화·직접 선택을 일반 잠재능력 장사와 같은 방식으로 사용하고, 일반 재설정과 프라임의 비용·횟수를 함께 반영
- 현재 스택에서 첫 매물을 처리할 때와 반복 장사의 장기 상태에서 매물당 기대 결과 표시
- 가격 입력과 프리셋은 브라우저에 저장

지원 범위와 확률·재설정 모델의 가정은 [에디셔널 잠재능력 장사 모델](docs/additional-trade-model.md)을 참고하세요.

## 추가옵션 장사

상단 **추가옵션 장사** 메뉴 또는 `#/flame-trade`에서 사용할 수 있습니다. 노작 보스 방어구·장신구를 사서 메소 추가옵션 재설정을 반복하고, 시세가 있는 추가옵션이 나오면 판매하는 장사의 기대 수익을 계산합니다. 옵션 확률·레벨별 수치·재설정 비용은 추가옵션 효율 계산기와 같은 모델을 사용합니다.

- 노작 매입가, 아이템 레벨 제한, 경매장 수수료, 잡추옵 처분가와 판매 대상 주스탯(STR·DEX·INT·LUK, 기본 전부) 입력
- **추가옵션 환산표**: 주스탯 1 = 1급 기준으로 부스탯·공격력/마력·올스탯 1%의 급수 입력 (기본 0.1·3·11급, 효율 계산기 기본 효율과 같은 비율)
- 오른쪽 **판매가** 패널에 추가옵션 수치와 시세를 쌍으로 추가. 수치는 환산 급수 합계 또는 주스탯·부스탯·공격력/마력·올스탯으로 입력하며, 결과는 도달한 가장 높은 기준의 가격으로 판매
- 여러 주스탯을 선택하면 각 주스탯의 고정 부스탯·공격력(INT는 마력)으로 환산한 급수 중 가장 높은 값으로 판매
- 판매·재설정 자동 최적화: 재설정 1회당 기대 이득이 최대인 판매 기준을 찾음 (수수료를 뺀 판매가가 노작 매입가보다 높은 구간은 바로 판매). 끄면 판매 조건 도달 즉시 판매
- 추천 판매 급수, 재설정 1회당 기대 이득, 매물당 기대 순익·재설정 횟수, 손익분기 노작 매입가, 100억당 기대 순익, 구간별 판정과 확률, 순익·재설정 횟수 분위수(정확 계산) 표시
- 재설정 비용 기본값 300만 메소, 입력과 프리셋은 브라우저에 저장

판매 정책·환산·한계는 [추가옵션 장사 모델](docs/flame-trade-model.md)을 참고하세요.
## 어빌리티 고급 재설정

상단 **어빌리티 전략** 메뉴 또는 `#/ability`에서 사용할 수 있습니다.

- 1~4순위 완성 옵션 세트와 각 옵션의 최소 수치·최소 등급 입력 (유니크 스탑 지원, 줄 순서 자유)
- 훈장 가격·메소마켓 시세로 명성치, 재설정 메소, 심연의 서큘레이터 비용 환산
- 모든 줄 배치·고정 조합·결과 유지·서큘레이터 전환을 비교하는 상태별 최적화
- 타협 범위별 비용, 기대 소모량, 완성 세트 비율, 상황별 다음 행동 조회
- 동일 결과 재추첨은 대표 모델에서 생략하고 그 효과를 감싸는 비용 범위를 표시

확률 출처, 상태 모델과 근사 범위는 [계산 모델 문서](docs/ability-model.md)를 참고하세요.

## 추가옵션 효율 계산기

상단 **추가옵션 효율 계산기** 메뉴 또는 `#/flame`에서 사용할 수 있습니다.

- 현재 추가옵션, 아이템 레벨 제한, 스텟별 효율, 주스텟 1%당 지불할 최대 메소 입력
- 기본 효율: 주스텟 10 = 1%, 부스텟 10 = 0.1%, 공격력·마력 10 = 3%, 올스텟 1% = 1.1%
- 보스 방어구·장신구의 추가옵션을 주스텟%로 환산해 중단·계속 판단 및 목표 추옵 조합 제시
- 추천 중단점·현재 추옵·조합 예시는 주스텟 환산 급수(예: 150급)로 표시하고 주스텟%는 보조로 제공
- 1회 300만 메소와 검은 환생의 불꽃 확률을 반영한 기대 재설정 횟수·비용·스텟 상승 계산

방어구·장신구만 계산하며 무기는 제외합니다. 일반 장비와 HP 기반 직업 등은 현재 지원 범위에 포함되지 않습니다. 확률 출처와 동일 결과 재추첨에 관한 근사 범위는 [계산 모델 문서](docs/flame-model.md)를 참고하세요.

## 에디셔널 잠재능력 전략

상단 **에디셔널 전략** 또는 `#/additional`에서 사용할 수 있습니다.

- 방어구·장신구, 현재 에디셔널 등급·세 줄 옵션, 캐릭터 레벨과 스탯 효율 입력
- 실패 스택은 장비 설정에서, 등급별 비용은 재설정 비용 카드에서 입력; 등급업 확률·천장은 고정값 적용
- 장사 메뉴와 공통 캐릭터·스탯 효율 패널 사용: 고정 부스탯·INT 마력 적용, 크뎀 1% = 주스탯 4% 기본, 드롭률·메소 획득량 제외
- 주스탯 1%당 지불 의향에 따른 수에큐·메소 재설정·혼합 전략 비교
- 수에큐 개당 가격 **+ 매회 감정비**, 메소 비용, 미라클, 등급별 누적 천장 반영
- **프라임 에디셔널 큐브 모드** 지원(가격 기본값 **14억 메소**). 자동 최적화는 현재 옵션에서 기대 스탯 상승의 가치와 총비용을 함께 비교하며, 프라임 기대 횟수·비용도 표시
- 에픽·유니크·레전드리별 종료 기준, 기대 비용·횟수·상승량·종료 등급 확률
- 원하는 x%를 직접 지정하거나 등급별 목표를 다르게 설정해 비교

첨부된 옵션 확률표가 있는 120~250레벨 구간만 지원하며, 제공되지 않은 부위·레벨 조합은 계산하지 않습니다. 세부 규칙과 근사 범위는 [에디셔널 계산 모델](docs/additional-model.md)을 참고하세요.

## 개발·검증

Node.js 20을 사용합니다. 의존성은 저장소의 lockfile로 설치합니다.

```bash
npm ci
npm test        # 전체 계산 엔진·데이터·저장 설정 검증
npm run build   # dist/index.html 생성 (CSS / Worker 포함)
python3 -m http.server 4173 --directory dist  # 로컬에서 생성 HTML 제공
```

브라우저 회귀 테스트는 빌드·임시 HTTP 서버·브라우저 정리를 자동으로 수행합니다.

```bash
npx playwright install --with-deps chromium  # 최초 한 번
npm run test:ui
```

시스템 Chromium이 있으면 이를 사용하며, 필요하면 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`로 실행 파일을 지정할 수 있습니다. UI 테스트는 메뉴 이동·모바일 레이아웃·실제 Worker 계산·입력 오류·저장 및 프리셋을 확인합니다. PR과 main 배포 모두 엔진·브라우저 테스트를 실행하며, 통과한 빌드만 gh-pages에 배포합니다.

새 기능을 추가할 때는 [공통 UI와 개발 지침](docs/ui-development.md)의 컴포넌트·레이아웃·계산 상태·검증 규칙을 재사용하세요. 두 에디셔널 메뉴의 환산 기본값은 한 곳에서 관리합니다. 기존의 유효한 사용자 지정값은 유지되며, 공통 패널의 **효율 기본값** 버튼으로 새 기본값을 적용할 수 있습니다.

## 방문 통계 설정 (GA4)

방문자 수와 페이지 조회수는 Google Analytics에서 확인합니다. 사이트에 공개 카운터를 표시하지 않으며, GA 계정·속성의 액세스 권한을 본인에게만 부여하면 통계 보고서도 본인만 볼 수 있습니다.

1. 현재 배포 대상은 측정 ID **`G-LT8GETTZFL`**인 GA4 웹 데이터 스트림입니다. Google Analytics에서 해당 스트림의 사이트 URL이 `https://serin511.github.io/maple-tools/`인지 확인합니다. 측정 ID는 배포 HTML에 포함되는 공개 설정값이며 보고서 열람 권한을 주는 비밀번호가 아닙니다.
2. 해당 웹 스트림의 **향상된 측정**을 끕니다. 사이트가 직접 페이지 조회를 보내므로 자동 기록을 함께 켜면 메뉴 이동이 중복 집계될 수 있습니다.
3. 배포 워크플로에 위 ID가 기본값으로 설정되어 있어 별도 변수 등록은 필요하지 않습니다. 다른 스트림으로 변경할 때는 GitHub 저장소의 **Settings → Secrets and variables → Actions → Variables**에 `GA4_MEASUREMENT_ID` 변수를 추가하면 기본값보다 우선 적용됩니다.
4. **Actions → Deploy to GitHub Pages → Run workflow**로 다시 배포합니다. 배포 워크플로는 엔진·브라우저 테스트를 통과한 뒤 실행하는 프로덕션 빌드에만 이 변수를 전달합니다.

배포 후 사이트를 열어 GA의 **실시간** 보고서에서 유입을 확인합니다. 계산기별 조회수는 **보고서 → 참여도 → 페이지 및 화면**에서 **페이지 제목**을 기준으로 확인하세요. 각 계산기는 `#/...` 경로와 고유한 제목을 사용하며, 최초 표시와 메뉴 이동·이전 페이지로 돌아갈 때 `page_view`를 보냅니다. 페이지 조회수는 새로고침이나 메뉴 재방문에도 늘어나므로 방문자 수와 다릅니다. 계산기 입력값과 프리셋 이름은 직접 보내는 이벤트에 포함하지 않습니다.

배포 워크플로 밖에서 측정 ID 없이 빌드하면 통계 수집은 꺼집니다. ID를 설정해도 `localhost`·루프백 주소와 `file:`로 연 개발 화면에서는 수집하지 않습니다. 브라우저 검증의 분석 요청은 테스트에서 가로채며 실제 GA로 보내지 않습니다. 아래는 배포와 같은 ID를 포함하는 로컬 빌드 예시입니다.

```bash
GA4_MEASUREMENT_ID=G-LT8GETTZFL npm run build
```
