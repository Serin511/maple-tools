# 추가옵션 효율 계산기

## 적용 범위와 입력

`#/flame`은 보스 방어구·장신구의 메소 추가옵션 재설정을 계산한다. 한 종류의 주스텟과 한 종류의 부스텟, 공격력 또는 마력, 올스텟%를 평가한다. 주스텟·부스텟 입력은 단일 스텟과 이중 스텟 추가옵션을 합한 최종 증가량이다. 공격력과 마력 중 자신의 직업에 유효한 한 종류만 입력한다.

계산 대상은 방어구·장신구로 한정하며 무기는 제외한다. 일반 장비의 옵션 개수·등급 분포, 두 종류 이상의 부스텟, 제논·데몬어벤져 등의 별도 효율 체계도 포함하지 않는다.

효율 입력은 주스텟 10당 1%, 부스텟 10당 0.1%, 공격력·마력 10당 3%, 올스텟 1%당 1.1%가 기본이다. 예를 들어 주스텟 100, 부스텟 50, 공격력 10, 올스텟 5%는 기본 효율에서 `10 + 0.5 + 3 + 5.5 = 19%`로 평가한다. 사용자의 효율은 이미 계산된 주스텟% 환산 비율로 취급하며 캐릭터의 실제 데미지를 다시 계산하지 않는다.

화면의 추천 중단점은 주스텟 수치로 환산한 **급수**로 표시한다. 주스텟 10당 효율을 e라고 할 때 `급수 = 주스텟% 환산값 * 10 / e`이다. 기본 효율에서는 `주스텟 + 부스텟 * 0.1 + 공격력·마력 * 3 + 올스텟% * 11`이며, 위 예시는 190급에 해당한다. 주스텟 효율을 바꾸면 급수 환산 비율도 함께 바뀐다. 소수 급수를 유지해 정수로 반올림한 값이 계산상 중단점을 바꾸지 않도록 하며, 주스텟%는 보조 정보로 표시한다. 주스텟 효율이 0이면 주스텟 수치로 환산할 수 없어 주스텟%로 표시한다.

## 비용과 확률

2026년 3월 19일 공식 업데이트는 메소 추가옵션 재설정 비용을 레벨과 무관하게 **3,000,000 메소**로 명시한다. 기존 옵션과 신규 옵션을 선택할 수 있고 옵션 등장 확률은 검은 환생의 불꽃과 같다.

- [공식 2026년 3월 19일 업데이트](https://maplestory.nexon.com/News/Update/799)
- [공식 추가옵션 확률표](https://maplestory.nexon.com/Guide/OtherProbability/game/gameAddOption)

보스 장비는 서로 다른 옵션 종류 4개를 균등하게 선택한다. 각 옵션의 등급은 4·5·6·7등급이 각각 29%·45%·25%·1%이다. 방어구·장신구의 기본 옵션 종류는 19개이며, 레벨 제한으로 등장할 수 없는 종류는 옵션 풀에서 제외한다.

레벨 제한을 L, 등급을 t라 할 때 단일 스텟은 일반적으로 `(floor(L/20)+1)*t`, 이중 스텟은 `(floor(L/40)+1)*t`이다. **250제 에테르넬 방어구의 단일 스텟은 예외적으로 `12*t`**이며, 4~7등급에서 48·60·72·84이다. 이 예외는 단일 주스텟과 단일 부스텟 모두에 적용한다. 250제 이중 스텟은 일반식대로 `7*t`(28·35·42·49)이다. 공격력·마력 증가량과 올스텟%는 t이다. 레벨 제한은 기본 레벨을 사용하며 착용 레벨 감소 추옵을 차감하지 않는다. 일반 수치 공식은 [추가옵션 수치 해설과 표](https://www.inven.co.kr/board/maple/2304/27668)를 참고하며, 250제 수치는 [에테르넬 추옵 표](https://meaegi.com/simulator/add-option/에테르넬%20메이지햇)와 사용자 확인을 반영한다.

평가에 무관한 옵션도 선택 확률에 포함한다. 유효 옵션의 부분집합을 열거한 뒤 남는 칸을 무효 옵션으로 채우는 조합 수로 가중하고, 유효 옵션의 등급을 모두 열거한다. 같은 유효 스텟 합계의 확률은 합산하되 서로 다른 종류의 중복 선택은 허용하지 않는다.

공식 시스템은 **직전과 완전히 같은 결과를 제외하고 재추첨**한다. 현재 입력은 유효 스텟의 합계만 받아 무효 옵션과 각 옵션 등급을 복원할 수 없으므로, 계산은 이 재추첨을 생략한 독립 시행 모델을 사용한다. 따라서 중단점과 기대 비용은 이 기본 분포 모델의 결과이며, 게임의 완전한 상태별 정밀 계산과는 경계에서 차이가 날 수 있다. 같은 환산 점수의 서로 다른 조합은 정상 결과이므로 제외하지 않는다.

## 최적 중단 방정식

추가옵션의 주스텟% 환산 점수를 X, 1회 재설정 비용을 c, 주스텟 1%당 지불할 최대 메소를 v라 한다. 최종 스텟의 가치 `v*X`에서 향후 재설정 비용을 뺀 기댓값을 최대화한다. 이미 쓴 비용은 중단 판단에 포함하지 않는다.

중단 경계 t는 다음 식을 만족한다.

```
v * E[max(X - t, 0)] = c
```

현재 점수가 t 이상이면 중단한다. 낮으면 재설정을 계속하면서 더 높은 결과를 유지하고, t 이상의 결과가 나올 때 중단한다. 실제로 등장 가능한 점수 중 t 이상인 최솟값을 화면의 목표 중단점으로 표시한다. 정확히 같은 가치라면 추가 비용 없이 중단하는 쪽을 선택한다. 지불 의향이 0이면 바로 중단한다.

목표에 도달할 확률을 q라 하면 현재 상태에서 계속하는 경우 기대 횟수는 `1/q`, 기대 비용은 `c/q`, 최종 점수는 `E[X | X >= t]`이다. 현재 상태에서 중단하면 향후 기대 횟수·비용·상승량은 0이다. 기대 횟수와 비용은 평균이며 최대 소모량이 아니다. 총예산·기간·일일 제한은 입력하지 않는 무한 기간 모델이다.

## 구현과 검증

새 설정은 별도 localStorage 키에 보관한다. 설정 변경 시 이전 결과를 숨기며 재계산은 이전 Worker를 종료한다. Worker와 CSS는 기존 어빌리티와 동일하게 단일 `dist/index.html`에 포함하므로 GitHub Pages 해시 경로와 파일 직접 열기에서 동작한다.

`npm test`는 효율 환산, 확률 질량과 옵션 중복, 레벨 경계, 독립적으로 계산한 평균 스텟, 단순 분포의 닫힌 식, 모든 채택 부분집합과 Bellman 방정식 비교, 0 지불 의향, 희박한 결과와 입력 오류를 확인한다. `npm run build`로 배포용 HTML을 생성한다.
