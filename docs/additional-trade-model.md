# 에디셔널 잠재능력 장사 계산 모델

이 문서는 상단 **에디셔널 잠재 장사** 또는 `#/additional-trade`의 장사 계산 모델을 설명한다. 기존 **에디셔널 전략**(`#/additional`)은 별도 계산기이며, 큐브 수단 선택과 스탯 효율 최적화를 다룬다.

## 입력 범위와 기본값

방어구·장신구 15개 부위 중 옵션 확률표가 있는 조합을 선택한다. 아이템 레벨은 140·160·200·250이며, 현재 입력된 시작 등급부터 확률표가 모두 있어야 계산할 수 있다. 무기·보조무기·엠블렘 및 표가 없는 부위·등급 조합은 지원하지 않는다. 시작 등급 기본값은 에픽이다. 재설정은 메소 방식만 계산한다.

가격 조건은 사용자가 행을 직접 추가한다. 기본 가격표나 성능 구간은 제공하지 않는다. 각 행에는 주스탯, 최소 환산값, 시세를 입력하며 모자에서는 쿨감 합계, 장갑의 크뎀 분리 모드에서는 크뎀 합계도 지정한다. 가격이 비어 있는 행은 판정에서 제외한다. 같은 주스탯·쿨감·크뎀 조건 묶음에서는 만족한 최소 환산값 중 가장 높은 행을 고른다. 서로 다른 묶음을 동시에 만족하면 판매가가 가장 높은 행 하나만 적용한다. 조건을 만족하는 여러 가격을 더하지 않는다.

쿨감과 크뎀은 입력한 합계 **이상**으로 판정한다. `0`은 해당 특수옵션 제한이 없다는 뜻이다. 모자의 쿨감은 항상 분리 판정한다. 장갑은 크뎀을 별도 가격 조건으로 보는 모드가 기본이며, 이때 크뎀의 스탯 환산 효율은 무시한다. 크뎀 분리를 끄면 크뎀을 다른 옵션처럼 사용자가 정한 환산 효율로 합산한다.

가격은 기본적으로 모든 등급에서 공유한다. 등급별 가격 입력을 켜면 에픽·유니크·레전드리 각각의 가격표를 입력할 수 있지만, 실제 계산에는 선택한 시작 등급 이상만 반영한다. **시작 등급 깡통 매입가**는 선택한 에디셔널 시작 등급에서 목표 옵션이 없는 아이템의 매입가다. 경매장 수수료도 입력하며, 가격은 판매 총액으로 본다. 양수인 레전드리 잡옵 처분가는 자동 최적화 모드에서 모든 레전드리 결과의 최저 처분가로 적용하며, 등록 가격이 더 높으면 높은 가격을 쓴다. 등록 가격 조건을 만족하는 결과가 없을 때도 이 하한가로 판매할 수 있다. 최적화를 끄고 등록 가격 조건에 맞는 결과를 모두 판매하는 모드에서는 도달 가능한 레전드리 가격 조건이 하나도 없을 때만 하한가를 미등록 결과의 대체 가격으로 쓴다.

크뎀 외 스탯의 기본 환산은 기존 에디셔널 전략과 같다. 주스탯 +10 = 주스탯 1%, 부스탯 +10 = 0.1%, 유효 공격력·마력 +10 = 3%, 부스탯 +1% = 0.1%, 올스탯 +1% = 1.1%다. 장사 계산기에서 크뎀 환산 기본값은 1%당 주스탯 4%이며, 일반 에디셔널 전략의 크뎀 기본값은 바꾸지 않는다. 장갑의 크뎀 분리 모드가 기본이므로 분리 모드에서는 이 환산값을 사용하지 않고, 분리를 끈 경우에 적용한다. 주스탯별 부스탯은 STR→DEX, DEX→STR, INT→LUK, LUK→DEX로 고정하며 INT의 유효 공격 스탯은 마력, 나머지는 공격력이다. 기준 캐릭터 레벨 기본값은 290이다. 9레벨당 스탯은 `floor(캐릭터 레벨 / 9)`를 옵션 수치에 곱한다. 제논용 올스탯 가격 모델과 데몬어벤져용 HP 가격 모델은 제공하지 않는다. 드롭률·메소 획득량 등은 가치를 0으로 처리한다.

메소 재설정 비용 기본값은 기존 에디셔널 재설정 비용표를 사용한다.

| 장비 레벨 | 에픽 | 유니크 | 레전드리 |
| --- | ---: | ---: | ---: |
| 140 | 27,300,000 | 66,300,000 | 78,000,000 |
| 160 | 29,050,000 | 70,550,000 | 83,000,000 |
| 200 | 30,800,000 | 74,800,000 | 88,000,000 |
| 250 | 34,300,000 | 83,300,000 | 98,000,000 |

비용은 재설정 전 등급을 기준으로 차감한다. 비용, 등급업 확률, 천장, 수수료는 상세 설정에서 조정할 수 있다.

## 등급과 천장

기본 등급업 확률은 에픽→유니크 0.9804%, 유니크→레전드리 0.7%다. 기본 누적 실패 한도는 각각 152회와 214회이며, 한도에 도달한 뒤 다음 재설정에서 등급업을 보장한다. 미라클 타임은 입력한 일반 등급업 확률만 2배로 적용한다(최대 100%).

현재 에픽·유니크 누적 실패 스택은 따로 입력한다. 판매 후 시작 등급의 새 매물을 구입해도 두 스택은 유지한다. 등급업이 발생하면 해당 등급의 스택만 0으로 초기화하고, 다른 등급의 스택은 유지한다. 실패하면 현재 등급의 스택을 1 올린다. 등급업 여부와 옵션 결과는 한 번의 재설정에서 함께 처리하며 재설정 비용은 재설정 전 등급 기준이다.

## 판매 정책과 결과

계산기는 매 재설정 뒤 결과를 관측하고 판매 또는 계속 재설정하는 정책을 평가한다. 자동 최적화를 켜면 시작 등급 깡통 매입가, 수수료, pity 상태와 이후 선택을 고려해 판매와 계속 재설정 중 장기 기대 이익이 큰 행동을 고른다. 끄면 가격 조건에 등록된 결과를 모두 판매한다. 이 정책 판단은 에픽에서도 적용되므로 에픽 상태의 가격 조건을 만족한 결과를 판매하고 현재 매물의 재설정을 끝낼 수 있다. 가격 조건에 걸리지 않은 결과는 계속 재설정한다. 매물이 판매되면 새 매물은 설정한 시작 등급으로 돌아온다.

목표는 반복 장사에서의 **안정 상태 재설정 1회당 기대 순이익**을 최대화하는 것이다. 옵션 조합 확률을 서로 배타적인 판매가 결과로 합친 뒤 유한 상태 평균 보상식을 수치 반복해 정책을 구하고, 그 정책의 pity 상태 분포를 계산한다. 레전드리 판매 가격이 없으면 등급과 천장 스택의 전이 순서를 따라 판매 후 새 매물을 시작하는 순환과 계속 재설정하는 상태의 장기 수익을 따로 비교해 정책을 구한다. 같은 레전드리 상태에서 계속 재설정하는 자기 반복은 기하분포 대기로 계산해 희귀한 판매 확률도 긴 횟수 제한으로 자르지 않는다. 이 결과에는 판매대금의 수수료, 재설정 비용, 매 판매 후 새 시작 등급 깡통 아이템의 매입가가 반영된다. 선택된 정책으로 처음 한 매물을 처리할 때의 매물당 기대값과, 이미 반복 장사를 진행한 뒤의 안정 상태 매물당 기대값 및 재설정 1회당 지표를 따로 표시한다. 시작 스택이 장기 pity 분포와 다를 수 있으므로 처음 매물과 장기 평균은 같지 않을 수 있다.

화면에는 현재 스택 기준 첫 판매까지의 기대 재설정 횟수·비용·매출·순이익과 등급별 횟수, 판매 시점 등급 비중을 표시한다. 반복 장사의 장기 상태에서도 매물당 기대 결과와 재설정 1회당 기대 순이익을 별도로 제공한다. 가격 조건 표의 **등급별 등장 확률**은 해당 행의 조건을 만족하는 결과의 확률이어서 행 사이에 겹칠 수 있다. **가격 적용 확률**은 최종 가격 판정에서 그 행이 선택된 결과의 확률이며, 최적 정책이 실제로 판매하는 확률과는 다르다. 선택한 등급·스택에서 결과별 판매/계속 판정도 확인할 수 있다. 최적화 정책이 끝내 매물을 판매하지 않는 경우에는 결과를 불가능으로 표시하고, 등록된 가격 조건을 모두 판매하는 정책의 참고값을 비최적 비교 결과로 보여준다.

## 확률 자료와 한계

옵션은 사용자가 제공한 에디셔널 메소 재설정 공식 확률표의 줄별 공개 확률을 사용한다. 출처·수집일·원본 파일 정보는 [에디셔널 계산 모델](additional-model.md#데이터와-비용)의 설명과 보존된 `data/additional-probabilities.json`에 기록되어 있다. 공개된 줄별 수치는 반올림 때문에 합계가 정확히 100%가 아닐 수 있어 각 줄 안에서 정규화한 뒤 세 줄을 독립 결합한다. 표가 없는 조합은 다른 레벨이나 부위 자료로 대체하지 않는다.

이 계산은 공개된 줄별 주변 확률을 독립 결합하는 모델이다. 직전과 완전히 같은 세 줄 결과를 다시 뽑지 못하는 규칙은 반영하지 않는다. 드롭률·메소 획득량 같은 효용 제외 옵션도 공개된 확률표에 나타나면 결과 확률 질량에는 포함하고, 환산 가치는 0으로 둔다. 스탯% 환산은 사용자가 정한 선형 효율이므로 실제 직업·장비 세팅의 비선형 가치를 자동 추정하지 않는다. 따라서 결과는 입력한 시세와 모델 가정 아래의 기대값이지, 실제 판매가나 게임 내 수익 보장이 아니다.

입력과 가격 조건은 브라우저의 로컬 저장소에 자동 저장된다. 이름을 붙인 프리셋도 이 브라우저에 저장되므로 다른 브라우저나 기기와 자동 동기화되지 않는다.
